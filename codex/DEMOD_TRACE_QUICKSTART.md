# 解调观测 V1 使用说明

## 当前状态

已经完成当前主工程的 FPGA、RX ARM 与 Windows 上位机配套实现。
支持 2FSK 和主工程的固定双门限 OOK；没有修改独立的 cyclone10_ASK / stm32_ASK 工程。
仿真、软件测试和编译不是板上实测。本次没有连接串口、烧录或改变硬件工作状态。

## 首次使用

1. 保留目前能工作的固件，再将发布目录中的 receiver_fpga.sof 和
   receiver_arm.hex 更新到接收端。SOF 是 FPGA 配置文件，不是持久化 Flash 的 JIC。
   发射端不需要为了诊断通道而更新固件。
2. 在发布目录的 host 子目录运行 short_trans_host.exe，保留其旁边的 DLL 和 data 目录。
3. 在通信页连接 RX 串口，仍为 115200、8N1。STATUS 中 FPGA 版本应为十进制 19。
4. 使用原有“调制与门限”页确认收发模式一致，然后点击工具栏“解调观测”图标。
5. 第一次选择“手动”和“触发后 128 ms”，点击“开始采集”，等待约半秒后点击闪电图标。
6. 上位机自动等待冻结并读取数据。图表不会将串口到达时间当作信号发生时间。

旧固件会明确返回不支持。仅替换上位机，不能让旧 FPGA 自动获得内部波形回传功能。

## 看图与调参

- 2FSK：看 E0、E1、总能量、载波门限、噪声估计、E1-E0、置信度和符号采样位置。
- OOK：看能量与真正生效的 LOW/HIGH 门限；迟滞区间内保持原判决。
- 多张图使用同一时间轴和游标，范围滑条可缩小时间窗口。
- 事件列表标出前导码、同步字、正确帧、CRC 错误、失锁、超时和削顶等事件。
- OOK 同步字的快速重放单独标为 REPLAY，不当作真实的符号采样点显示。
- 能量数值是 FPGA 内部定点处理单位，不是伏特或 dBm；对数显示为 log10(1+E)。
- 先完成一次采集，再回到原有设置页调整 OOK 门限，确认回读生效后重新采集。
- 本版记录 FSK 已生效的参数，但没有新增 FSK 在线调参事务，也不会自动修改任何门限。

## 触发建议

| 目标 | 触发条件 | 触发后点数 |
| --- | --- | --- |
| 初次确认曲线正常 | 手动 | 128 |
| 看锁定过程 | 锁定 | 128 或 256 |
| 看帧尾为何 CRC 失败 | CRC 错误 | 0 或 64 |
| 看失锁前发生了什么 | 失锁 | 64 |

以上是采集方式建议，不是推荐的解调判决门限。

缓冲区最多 512 点，指标间隔为 1 ms。满缓冲的首尾点相距 511 ms。
触发后的点数越多，留给触发前的历史就越少；刚开始就触发时历史可能不足。
100 bit/s 下整帧可能长于缓冲区，因此 CRC 触发记录可能只包含帧尾。
事件定位粒度约为一个指标间隔，不能将事件标记解释为精确的 FPGA 时钟级时间戳。

## 保存与回放

保存按钮同时导出 CSV 和原始 .dtr，位置为程序工作目录下的 exports/traces。
文件夹按钮可以按路径打开 .dtr，不需要连接硬件。
CSV 保留数值、采样计数、配置和事件；.dtr 保留完整采集头与原始记录。
仿真截图和测试文件不是板上采集结果，应与真实测量分开保存。

## 中断与边界

- 等待触发超过 30 秒，上位机会停止并取回中断前的数据。
- 点击停止会冻结已有数据；读取阶段再次停止可以取消下载。
- 配置变化、扫频占用或 ADC 链路复位会中断采集，界面明确标注，不拼接不同配置。
- 传输使用分块 CRC 校验；失败可重读同一块，最多尝试三次。
- 解调继续运行，不等待诊断数据读取；板端同一时刻仅保存一份记录。
- 本版尚不包含连续实时概览、原始 ADC 波形页、直方图或自动门限优化。
